# Project notes for the agent

- What it is: one grid of every NCAA Division I (and National Collegiate) national champion since 1972, 33 sports, one school mark per title. A reader picks schools (`?s=School`, repeatable) and every other title those schools won lights up across the grid and the leaderboard. It was split out of cfb-all-time-records, which kept the football records table; this repo is the grid alone so the URL isn't football-specific. README.md has the sport-selection rule (two of three lenses: sponsorship, popularity, Olympic relevance) and the scraper's details.

- Data: Wikipedia, CC BY-SA. `node scripts/fetch-data.mjs` scrapes each sport's champions table into `src/championshipData.scraped.json` (committed); `src/championshipData.js` holds `SPORTS`, `SCHOOLS` (names, marks) and the per-sport memory overrides for years Wikipedia lacks, and `scripts/gen_champs.mjs` regenerates that block after a re-scrape. `scripts/diff_scraped.mjs` shows what changed upstream; `scripts/reconcile.mjs` reports schools the data names that `SCHOOLS` lacks. Adding a sport is one entry in `SOURCES`. Refresh is manual: re-run when a season's champions are final, read the diff, commit. Football's consensus champion per season is CFP > BCS > AP > Coaches, both schools in the split seasons.

- Code layout: Vite + React, plain JS. `src/ChampionshipGrid.jsx` is nearly the whole page, styles included (the `STYLES` string, injected as a `<style>`; keep it in one component unless a split is tiny). `src/lib/champs.js` is the pure data layer (titles, leaderboard, URL parse/print), `src/lib/share.js` the words for the page, the share text and the worker, `src/lib/siblings.js` the other sports sites in the shared order (the page and llms.txt both read it), `src/components/SchoolPicker.jsx` the finder (Radix dropdown on desktop, vaul sheet on phones).

- The page, top to bottom: the h1, the sentence with the picked schools as chips and a dashed `+`; the icon bar (coffee, share); the grid and the leaderboard; the Method as `<section id="method">` with an open intro (the sport rule and the Wikipedia credit) and four `<details>` folds (where the data comes from, what counts as a championship, what the words mean, where a published number differs); the Ko-fi line; What to read next; the footer. Ko-fi is tracked `kofi` with `from: 'icons' | 'notes' | 'footer'`; share is `navigator.share` with the page's sentence, else copy "text url" and flash copied, tracked `share` with `from: 'icons'`. A number on the page comes from the data (`SPORTS.length`, `FIRST`), never typed in.

- Build and deploy: `npm run build` is `vite build` plus `scripts/prerender.mjs` (the rendered page, WebPage JSON-LD, `sitemap.xml`, `llms.txt` via `scripts/lib/llms.mjs`). There are no tests and no typecheck; the build is the check. `.github/workflows/deploy.yml` deploys to GitHub Pages on every push to `main`, then the `worker` job deploys the share worker with `CLOUDFLARE_API_TOKEN`. No cron. Dev server: `npm run dev` on 5173; `.claude/launch.json` also has the preview (4174) and the worker (8788).

- The share worker (`workers/share/`) sits on `drewhoover.com/collegiate-championships/*`. A `?s=` address gets its own title, description and og tags from `src/lib/share.js`, and `og:image` points at `/share/og.png`, drawn by `card.ts` with workers-og from the data the bundle carries: one school's titles by sport, or several side by side. `CARD_VERSION` in `index.ts` keys the edge cache: bump it with any change to what a card draws. Anything that fails passes through untouched. `npm run worker:dev` runs it locally with `NO_REPORT=1`.

- Look: its own palette on purpose (`--bg #2e2a2c`, Oswald and Barlow, Source Serif 4 for the title, fonts by `@import` in `STYLES`). Take the sports chrome (the back bar's `data-section="sports"`, the sibling list, the Method folds, the three Ko-fi placements) and leave the colors.
